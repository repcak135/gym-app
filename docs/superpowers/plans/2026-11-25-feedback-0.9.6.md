# Banana Gym 0.9.6 (friends' feedback) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gym slang + user alternative names in search, "Utwórz własne ćwiczenie" from every picker, inline set editor, rest-end on return, release 0.9.6.

**Architecture:** Search stays in `filterExercises` (`src/data/exercises.ts`); it gets two more name sources: a built-in slang map (`src/data/slang.ts`, id → Polish slang names) and `Exercise.userNames` (stored on the exercise row like `weightStep`, so it survives reseed and rides in backup `exerciseOverrides` / `customExercises`). The picker gets a create row that opens the existing exercise form (extracted into a reusable `ExerciseForm` component) in a sheet. The set editor moves inside the selected `<li>`. RestBar plays the end sound once on return and passes "how long ago" to the banner.

**Tech Stack:** React 19, Dexie 4, Vitest + Testing Library, Playwright, Vite PWA.

**Spec:** the task brief from the parent session (items 1–4 + release).

**Update (owner): the reporting friend uses ANDROID.** Research:
- Chrome on Android throttles timers of a hidden page and freezes it after ~5 min (Android-only freezing intervention, blink-dev "Freezing task queues in background on mobile"); audible pages are exempt, silent audio is not counted as audible (Chrome "background tabs" post, Mozilla 1336484). Wake Lock is released when the screen goes off; `navigator.vibrate` needs a visible page; a notification at rest end would need JS to run at that moment (same problem; Notification Triggers were abandoned).
- Media elements keep playing in the background on Android and take audio focus (Chromium audio_focus.md; Web Audio does not take focus).

**Shipped (Android only, default OFF): "Graj w tle (eksperymentalne)"** — `src/audio/backgroundRest.ts` builds one 8 kHz 8-bit WAV per rest (silence for the rest's length, 3-2-1 ticks and the preset's end sound baked in) and plays it through `<audio>`, so nothing has to run in JS at the end. The Web Audio schedule is skipped while it plays; "Pomiń" / +15 s stop or rebuild it; the return fallback does not replay when the file reached its end. Costs (in the Settings note): media notification, battery, may pause other apps' music, no vibration with the screen off. Not verifiable on a real Android phone from here: needs a check by the friend.

**iPhone: not offered.** Home Screen web apps stop media/Web Audio when locked (WebKit 198277, 173332, 295518, 291892; iOS 26 regressions), no confirmed fix.

Settings note is platform-aware (Android / iPhone / nothing on desktop). E2E project `android` (Pixel 7, 412×915) runs `android.spec.ts` + `names-and-create.spec.ts`.
