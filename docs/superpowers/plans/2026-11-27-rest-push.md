# Rest-end push notification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When a rest ends while Banana Gym is hidden or the phone is locked, a Cloudflare Worker sends a Web Push "Koniec przerwy".

**Architecture:** A Worker in `server/` routes `/subscribe`, `/schedule`, `/cancel` to one Durable Object per device id; the object stores the subscription and one pending push and sets a storage alarm; the alarm sends an encrypted Web Push (VAPID ES256 + aes128gcm, our own small implementation on Web Crypto). The app sends `/schedule` on hide and `/cancel` on show (one hook mounted in `App.tsx`), and a tiny `public/push-sw.js` imported into the Workbox service worker shows the notification.

**Tech Stack:** Cloudflare Workers + SQLite Durable Objects (free plan), wrangler, TypeScript; React 19, Dexie, vite-plugin-pwa; Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-27-rest-push-design.md`

## Global Constraints

- Free plan only: Workers + SQLite-backed Durable Objects. No Queues, no cron, no paid features.
- No workout data on the server: only the push subscription, one pending `endsAt` and a short title/body. Pending entry deleted after sending.
- VAPID private key only as a Cloudflare secret (`VAPID_PRIVATE_KEY`); never in git. Public values (`VITE_PUSH_URL`, `VITE_VAPID_PUBLIC_KEY`) committed in `.env` (all build modes, so tests see them too).
- CORS origins: `https://repcak135.github.io`, `http://localhost:5173`.
- Push endpoints accepted only on hosts `web.push.apple.com`, `fcm.googleapis.com`, `*.push.services.mozilla.com`, `*.notify.windows.com`.
- Device id: random 128-bit (32 hex chars). `endsAt` within the next 30 minutes. Body ≤ 4 KB. ≤ 60 `/schedule` per device per hour.
- Notification: title "Koniec przerwy", body "Seria N · <exercise name>" or "Czas na kolejną serię"; `tag: 'rest'`, `data.url: '#/trening'`.
- Setting off by default; push id and switch are device-only (`DEVICE_ONLY` in `backup.ts`).
- iPhone: if not running as installed app (not `display-mode: standalone`), the switch is disabled with a one-line hint. Setting hidden when the build has no push config.
- Version 0.9.17, Polish changelog entry that says what leaves the phone. Polish copy is gender-neutral.

## Review Focus

1. Lock while a rest is running, unlock after the rest ended → no push while visible; in-app "Koniec przerwy" bar still shows (cancel on show).
2. Lock with no rest running → nothing sent.
3. Permission denied or `pushManager` missing (Safari tab, old iOS) → switch stays off with a Polish message, no crash.
4. Push service answers 404/410 → Durable Object forgets the subscription; later `/schedule` returns 404 and the app turns the switch off quietly on next show.
5. Malicious caller: endpoint on another host, `endsAt` 2 h ahead, 5 MB body, unknown id → 4xx, nothing stored.

### Task 2: Device Durable Object and router

**Files:** Create `server/src/device.ts`, `server/src/index.ts`, `server/src/validate.ts`; tests `server/src/device.test.ts`, `server/src/index.test.ts`; `server/wrangler.toml` (`new_sqlite_classes = ["Device"]`, `observability.enabled = true`), `server/package.json`, `server/README.md`.

**Interfaces — Produces:**
- `class Device { constructor(state: DurableObjectStateLike, env: Env); fetch(req: Request): Promise<Response>; alarm(): Promise<void> }` — internal paths `/subscribe` (PUT sub), `/schedule`, `/cancel`, `/forget`.
- Storage keys: `sub: PushSub`, `pending: {endsAt, title, body}`, `hits: number[]` (schedule timestamps, last hour).
- `isAllowedEndpoint(url: string): boolean`, `parseSchedule(body: unknown, now: number): {endsAt, title, body} | null` (title ≤ 60 chars, body ≤ 120 chars).
- Worker routes: `POST /subscribe {subscription}` → `{id}`; `POST /schedule {id,endsAt,title,body}` → 204 / 404 unknown id; `POST /cancel {id}` → 204; `DELETE /subscribe {id}` → 204. OPTIONS preflight. Ids must match `/^[0-9a-f]{32}$/`; object name = id.

- [ ] Tests with an in-memory storage fake: schedule stores pending + `setAlarm(endsAt)`; second schedule replaces; cancel deletes both; alarm sends once and deletes pending; alarm with 410 deletes `sub`; 61st schedule in an hour → 429; router rejects a bad origin (403), endpoint on `evil.example` (400), `endsAt` > 30 min (400), body > 4 KB (413), unknown id (404).
- [ ] Implement; run tests; `wrangler deploy`; commit.
