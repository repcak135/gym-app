# Friends' ranking and accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Opt-in friends' ranking (workouts per week/month, bench DOTS points) with nick + password accounts on the existing Cloudflare Worker.

**Architecture:** D1 (`banana-gym`) holds members, sessions, scores and login attempts. The phone derives a PBKDF2 key from the password (salt handed out by the server, iterations stored per member) and sends only that; the server stores `SHA-256(serverSalt‖key)`. A `RankingSync` component recomputes the phone's current scores from Dexie live queries and posts them whenever they differ from the last successful send, which covers finish/edit/delete/restore/Ciało/app start.

**Tech Stack:** Cloudflare Workers + D1 (free), Web Crypto; React 19, Dexie; Vitest (Worker tests run real SQL on `node:sqlite`), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-27-ranking-design.md`

## Global Constraints

- Never on the server: body weight, sex, kilograms, exercise lists, notes, the plain password.
- Nick `^[\p{L}\p{N}_-]{3,20}$` (NFC), unique by `toLocaleLowerCase('pl')`, shown as typed. Password ≥ 8 chars.
- PBKDF2-SHA-256, 300 000 iterations (per member, versioned), salt = 16 random bytes from the server, 32-byte key, base64url.
- Session token 128-bit hex, stored only as SHA-256 on the server; device-only on the phone (not in backups).
- Failed logins: 5 per nick and 20 per IP-hash per 15 min; joins: 5 per IP-hash per hour (IP stored only as SHA-256).
- Admin token and any secret only as Cloudflare secrets (`ADMIN_TOKEN`); copies in `C:\Claude\gym-app-private\`.
- Week = ISO week Monday–Sunday local (`2026-W48`), month `2026-11`. Score rows older than 92 days deleted.
- Bench = flat barbell bench ids only: `Barbell_Bench_Press_-_Medium_Grip`, `Wide-Grip_Barbell_Bench_Press`, `Close-Grip_Barbell_Bench_Press`, `og-0122` (wide), `og-5013` (pause), `og-6584` (feet flat). Heaviest completed working set with reps ≥ 1, stored weight, kg.
- Body weight: latest Ciało entry ≤ 60 days old, else bench is not shared until one is entered.
- Join endpoint accepts an optional `code`; required only when the `JOIN_CODE` secret is set.
- Polish gender-neutral copy; version 0.9.20.

## Review Focus

1. Login with the wrong password 6 times → the 6th answers 429 even with the right password; after 15 min it works.
2. Two phones logged in, password changed on one → the other's token stops working (401) and the app shows the login form, not a crash.
3. Bench shared but no recent Ciało weight → only workouts are sent; the screen asks for the weight.
4. Member stops sharing bench → their bench rows disappear from the table at once.
5. Offline finish → nothing lost; the next app start sends the scores.

### Task 1: D1 schema and Worker account routes

**Files:** Create `server/migrations/0001_ranking.sql`, `server/src/accounts.ts`, `server/src/accounts.test.ts`, `server/src/d1-node.ts` (test adapter over `node:sqlite`); modify `server/src/index.ts`, `server/wrangler.toml` (`[[d1_databases]] binding = "DB"`).

**Interfaces — Produces (HTTP, JSON, CORS as push + `Authorization` header):**
- `GET /account/salt?nick=` → `{salt, iterations}` | 404
- `POST /account/join {nick, salt, iterations, key, shareWorkouts, shareBench, code?}` → `{token, nick}` | 409 nick taken | 400 | 403 code | 429
- `POST /account/login {nick, key}` → `{token, nick, shareWorkouts, shareBench, mustChange}` | 401 | 429
- `GET /account/me` (Bearer) → same fields without token | 401
- `POST /account/password {salt, iterations, key}` (Bearer) → 204, other sessions ended, `mustChange` cleared
- `POST /account/sharing {shareWorkouts, shareBench}` (Bearer) → 204; turning one off deletes those score rows
- `DELETE /account/session` (Bearer) → 204; `DELETE /account` (Bearer) → 204, everything deleted
- `POST /scores {week, month, workoutsWeek?, workoutsMonth?, benchWeek?, benchMonth?}` (Bearer) → 204
- `GET /ranking?week=&month=` (Bearer) → `{week: {workouts: Row[], bench: Row[]}, month: {...}}`, `Row = {nick, value}` sorted desc, workouts include sharing members with 0
- `POST /admin/reset {nick, salt, iterations, key}` and `POST /admin/remove {nick}` (Bearer `ADMIN_TOKEN`)
